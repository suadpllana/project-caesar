All done. The loader now produces `run u3 s1 u1` on `tiny.txt`, and both big programs finish in about 1.5 seconds each, well inside the 60-second budget for the whole graded set.

**What was wrong and what I changed** (only the six permitted files under `/app/link/`):

- **pick.py**: a fallback publication was ranked behind any ordinary one. Now the first live, visible publisher in order answers, regardless of kind. Publications are also indexed by name and by scope, so a call no longer scans thousands of invisible publishers. That scan was why `wide.txt` took 58 seconds.
- **view.py**: visibility always returned true. It now allows a publication only when it is public or sits in the caller's scope.
- **walk.py**: `open` gives everything one activation brings up a single fresh scope, `act` publishes public, and `act` on a unit already up in a scope exposes that same publication in place. Startup calls now run right after the unit's own `up`, not after the whole activation. A unit coming up clears its settled uses and gets a new publication generation.
- **site.py**: a settled use now remembers which publication it settled on, so a unit of the same name coming back up does not repair a dead call.
- **want.py**: `pre` no longer keeps a unit up. Only holds and live hard dependents count, tracked with a counter instead of a full scan.
- **drop.py**: the sweep took the first unwanted unit in order instead of the last. It now repeatedly takes down the last one via a heap, which also makes the 18,000-unit teardown fast.

**Verification**: all five small programs match the stated rules by hand. On `wide.txt`, the indexed lookup produces byte-identical output to a plain linear scan over the publication order. An extra program exercising scoped visibility, exposure through `act`, `pre`, and teardown order behaved as specified.

One judgment call: a unit that names itself as a dependency does not keep itself up. That matches the behaviour the previous code had, and none of the shipped programs contain a self-dependency.
