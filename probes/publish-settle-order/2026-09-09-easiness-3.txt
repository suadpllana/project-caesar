All checks pass. Here is the recap.

**Root causes** in the rewritten loader, all fixed within the six permitted files:

- **Fallback picking** in `link/pick.py` skipped fallback publications in favour of any later ordinary one. Now the first live, visible publisher in publication order wins, fallback or not. This fixes the `tiny.txt` result, which now ends `run u3 s1 u1`.
- **Scopes were unimplemented.** `view.can` returned true for everything. `open` now assigns one fresh scope to everything it brings up, `act` publishes publicly, and `act` on an up scoped unit makes it public in place.
- **Startup calls ran too late.** They now run right after their unit is published, before the walk continues.
- **Settled uses survived restarts.** A use now records the publication generation, so a unit coming back up does not repair a dead call, and a unit coming up starts with nothing settled.
- **Take-down was wrong and slow.** `pre` units counted as keeping their unit up, the sweep took the first rather than the last unwanted unit, and it rescanned every unit per pass. It now keeps a live dependent count per unit and pops candidates from a heap ordered from the back.
- **Deep walks** are done with an explicit stack rather than recursion.

**Performance.** Lookups are indexed by symbol and scope, since each symbol in `wide.txt` has about five thousand publishers.

| program | time |
|---|---|
| wide.txt | 2.6 s |
| tear.txt | 1.7 s |

Three of each plus the small programs fit comfortably inside the 60 second budget.

**One assumption to flag.** Units that depend on each other in a cycle keep each other up after all holds are released, since the rules say a unit stays up while any up unit names it as a dependency. `pair.txt` therefore prints no `down` lines. If the shipped loader should break such cycles, that rule in `link/want.py` is the place to change.
