`/app` is the scan layer of a columnar store, cut down to the part that decides which chunks get read. A segment file holds one table and the queries to run over it. `/app/run_scan.py` takes one and prints what happens. `seg G N K` opens the file with the statistics granularity, the row count and the column count. Rows and columns are numbered from 0. `ch C n u mn mx x e ...` is one chunk of column C over n rows, u of them null, with mn and mx the recorded low and high over the rest, x either `e` or `w`, and e either `p` or `d`. A column's chunks appear in row order and cover every row of the table. Chunks are numbered from 0 within their column. The partitions of two columns need not line up. A `p` chunk lists its n values, `-` for a null. A `d` chunk gives its dictionary size, then the entries ascending, then one token per row: an index into the dictionary, `-` for a null, or `*` and a value the dictionary does not hold. `qry` opens a query, `prd` carries one condition, `prj` names the columns to report and `end` closes it. A condition is `ge C v`, `le C v`, `eq C v` or `ne C v` against a value, or `nn C` and `nu C` for not-null and null. A null satisfies `nu` and nothing else. Every query names at least one condition and at least one column. `/app/segs` holds four segment files.

The recorded low and high cover the values of a chunk that are not null. Call those its live rows. Under `e` the recorded pair is the pair to use. Under `w` it was rounded inward to a multiple of G, so the low to use is the recorded low less G-1 and the high is the recorded high plus G-1. A chunk whose nulls are all its rows writes both as `-` and has no bounds.

A chunk is dropped unread when the header proves no row of it satisfies the condition, and kept unread when the header proves every row does. What proves the first is the high below v for `ge v`, the low above v for `le v`, v outside the bounds for `eq v`, a low and a high that are both v for `ne v`, no live rows at all for `nn`, and no nulls at all for `nu`; what proves the second is the low at least v for `ge v`, the high at most v for `le v`, a low and a high that are both v again for `eq v`, v outside the bounds again for `ne v`, no nulls for `nn`, and every row null for `nu`. Apart from `nu`, a chunk holding any null is never kept unread, and a chunk with no live rows is dropped unread under a comparison as it is under `nn`.

Neither test settles what gets read first. For that a condition has a count on a chunk: the live rows spread evenly over the bounds. Take two widths. One is the width of the bounds, the high less the low plus one; the other is the width of the part the condition asks for. That part is the high less v plus one for `ge v`, v less the low plus one for `le v`, and one for `eq v` and `ne v` when v lies within the bounds and none when it does not. Where it comes out at nothing or less the count is zero for `ge v`, `le v` and `eq v`, and every live row for `ne v`. Otherwise cut the part down to the width of the bounds, multiply the live rows by it, divide by that width and round up. That is the count for `ge v`, `le v` and `eq v`, and for `ne v` it is the live rows less it. `nn` counts the live rows and `nu` counts the nulls, and a chunk with no live rows counts nothing for anything but `nu`.

A chunk the header has settled never reaches its dictionary. A `d` chunk none of whose tokens is a value written with `*` can answer a comparison from its dictionary alone. That dictionary is charged once. The first condition to reach it prints `rd` with the column and the chunk number, and a later one on the same chunk prints nothing. No entry satisfying the condition drops the chunk; every entry satisfying it with the chunk holding no nulls keeps it; anything else reads the chunk. `nn` and `nu` are never answered from a dictionary. Nor is a chunk that has already been read.

Reading a chunk prints `dc`, the column and the chunk number. It settles the exact count of every condition of the query over that column, counted over all of the rows of the chunk rather than over the rows still alive, and that count stands in for the spread on that chunk from then on. The condition being applied then drops the surviving rows of the chunk that do not satisfy it.

A condition and a chunk of its column are a pending pair while the condition has not been applied to that chunk and the chunk still holds a surviving row. The pair taken next is the one expected to leave the fewest rows alive, which is the smaller of the rows that chunk still holds and the count of the condition on it. A tie goes to the condition written earlier in the query. Then to the lower chunk number. The conditions are done when nothing is pending.

import sys

from scn import emit, live, parse, pick, proj


def run(text):
    seg, queries = parse.load(text)
    out = emit.Out()
    for i, q in enumerate(queries):
        out.qry(i)
        st = live.start(seg, q)
        pick.run(seg, q, st, out)
        rows = live.rows(st)
        out.sel(len(rows), emit.digest(rows))
        proj.run(seg, q, st, rows, out)
    return out.lines


def main():
    with open(sys.argv[1], encoding="utf-8") as fh:
        text = fh.read()
    sys.stdout.write("\n".join(run(text)) + "\n")


if __name__ == "__main__":
    main()

def bounds(seg, ch):
    if ch.mn is None:
        return None
    return ch.mn, ch.mx


def miss(seg, ch, cond):
    k = cond.kind
    if k == "nu":
        return ch.nulls == 0
    have = ch.n - ch.nulls
    if have == 0 or k == "nn":
        return have == 0
    lo, hi = bounds(seg, ch)
    v = cond.v
    if k == "ge":
        return hi < v
    if k == "le":
        return lo > v
    if k == "eq":
        return v < lo or v > hi
    return lo == hi == v


def allsat(seg, ch, cond):
    k = cond.kind
    if k == "nu":
        return ch.nulls == ch.n
    if k == "nn":
        return ch.nulls == 0
    lo, hi = bounds(seg, ch)
    if lo is None:
        return False
    v = cond.v
    if k == "ge":
        return lo >= v
    if k == "le":
        return hi <= v
    if k == "eq":
        return lo == hi == v
    return hi < v or lo > v


def guess(seg, ch, cond):
    k = cond.kind
    if k == "nu":
        return ch.nulls
    have = ch.n - ch.nulls
    if have == 0 or k == "nn":
        return have
    lo, hi = bounds(seg, ch)
    v = cond.v
    span = hi - lo + 1
    if k == "ge":
        room = hi - v + 1
    elif k == "le":
        room = v - lo + 1
    else:
        room = 0 if (v < lo or v > hi) else 1
    if room <= 0:
        return have if k == "ne" else 0
    if room > span:
        room = span
    part = -(-have * room // span)
    return have - part if k == "ne" else part

class State:
    __slots__ = ("seg", "alive", "own", "vals", "hit", "dread", "done")


def _cols(q):
    seen = []
    for cd in q.conds:
        if cd.c not in seen:
            seen.append(cd.c)
    for c in q.cols:
        if c not in seen:
            seen.append(c)
    return seen


def start(seg, q):
    st = State()
    st.seg = seg
    st.alive = set(range(seg.n))
    st.own = {}
    st.vals = {}
    st.hit = {}
    st.dread = set()
    st.done = [set() for _ in q.conds]
    for c in _cols(q):
        own = []
        for ch in seg.cols[c]:
            own.extend([ch.j] * ch.n)
        st.own[c] = own
    return st


def count(st, c, j):
    ch = st.seg.cols[c][j]
    lo = ch.start
    hi = lo + ch.n
    t = 0
    for r in st.alive:
        if lo <= r < hi:
            t += 1
    return t


def kill(st, dead):
    st.alive.difference_update(dead)


def drop_chunk(st, c, j):
    ch = st.seg.cols[c][j]
    kill(st, range(ch.start, ch.start + ch.n))


def filter_chunk(st, c, j, cond, vals):
    ch = st.seg.cols[c][j]
    s = ch.start
    kill(st, [s + i for i in range(ch.n) if not rd.sat(cond, vals[i])])

**What was wrong** in the scan layer, and what I changed across the six permitted files:

- `scn/hdr.py`: bounds now widen by G-1 under `w`. Keep-unread now refuses any chunk holding nulls except for `nu`, and handles missing bounds.
- `scn/dct.py`: a dictionary chunk with a `*` token is no longer answered from its dictionary. The `rd` line prints only the first time a chunk's dictionary is charged.
- `scn/step.py`: reading a chunk now records the exact count for every condition on that column, not just the one being applied.
- `scn/pick.py`: replaced the fixed per-condition ordering with the dynamic pending-pair rule, picking the smaller of surviving rows and count, tie on condition position then chunk number, re-evaluated after each step.
- `scn/live.py`: per-chunk alive counts kept incrementally per column instead of scanning the whole alive set per lookup.
- `scn/proj.py`: columns reported in the order named and once per naming. Only chunks that still hold survivors and were not read get read.
