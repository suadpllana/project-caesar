The tree under `/app` is the front half of a streaming server we put in front of our own models. A model produces bytes a token at a time and the server decides, after every token, how much of the response it can put on the wire. What has gone out has gone out. There is no taking a byte back. `/app/run_stream.py` takes a job file and prints what happened, a row per event: which token the model produced, which bytes went to the client at that step, which tool call was dispatched and what it answered, which script that answer moved the model onto, whether the response was declared over, and the whole client text at the end. `/app/runs` holds four jobs to try it on. Run them.

Two kinds of bracket run through what a model writes. An aside opens with `<~` and closes with `~>`, and the client never sees one: the two markers and everything between them are dropped. A quote opens with `<#` and closes with `#>`, and the client sees every byte of it, but nothing inside a quote counts as anything, so a stop string that falls there does not end the response and a tool call written there is not a call. Neither kind nests. Neither opens inside the other. An opener whose closer never arrives is ordinary text with no meaning at all, and the scan carries on from just past it, so a bracket of the other kind can still form later. A closer may not overlap the opener it shuts, so `<~>` is an opener with a `>` behind it and no aside anywhere in it. A closer standing on its own is ordinary text too. Nothing else is a bracket.

The rest of the rendering is short. A job carries stop strings, and the response ends at the first place one of them occurs in what the client can see with no byte of the match inside a quote; neither the stop nor anything after it is sent. A tool call is `{`, then one or more lowercase letters, then `}`. The server dispatches the calls it finds in the order they appear, once each; a tool's answer can move the model onto a different script, so what the model says next depends on when the call went out, and a call that goes out two steps later than it could have takes the model down the same branch two steps later than it should. Timing changes the transcript.

Here is what we hold the server to. Both halves of it are graded as hard as each other.

No byte may go to the client that the finished response would not contain, and every byte the finished response does contain has to go the moment nothing else could take its place. Sending early is wrong. Sitting on a byte that was already settled is wrong as well, and the trace carries the step each byte went out on, so a byte released one token late is as visible as one released a token early. A tool call is a side effect that cannot be taken back, so it waits for the same certainty the bytes do, and it goes out the moment it has it. The response is declared over when nothing the model could still write would add to it. Not before.

The model may stop after any token it likes. We do not tell the server in advance which one that will be. It could be the next one. The jobs we grade have openers that close many tokens later, openers that never close at all, and openers still waiting when the model stops; they carry stop strings and calls on both sides of all three, their stop strings are built out of marker bytes as often as out of letters, and they write the two bytes of a marker across a token boundary as often as inside one. Some of them reach the script holding their second call only because the first one was dispatched.

Four things have to keep working and we grade them as hard as the rest. A response with no brackets and no stop in it streams out a token at a time with nothing held back. A closed quote with a stop string inside it runs past that stop to the end. A closed aside with a call inside it makes no call. A stop in plain text ends the response on the step it lands. All four are in the graded set.

We grade the trace and the client text, in order, exactly, with no partial credit. We grade the jobs in `/app/runs`, a harder set you have not seen, and several hundred more built after your work is finished, so a rule that happens to fit the four in front of you will not carry.
