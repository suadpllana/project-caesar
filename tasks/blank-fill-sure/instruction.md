`/app` is the query side of the store we merge customer records into. Sources leave gaps, and a value no source supplied is kept as a placeholder with a label: `?w` in one row and `?w` in another are the same unknown value, whatever it is. Every column says which values it allows. A report says, for each query, which rows the store returns whatever values the placeholders turn out to have.

A program is a text file and `/app/progs` holds a few. `/app/run_ask.py <program>` prints its report.

A program is made of lines of three kinds, with every `table` line first. `table <name> <allowed> ...` declares a table with one allowed set per column: `lo..hi` allows every integer from lo to hi, both included, where 0 <= lo <= hi <= 999999999, and `a|b|c` allows exactly the symbols listed. `row <table> <value> ...` adds a row. A value is an integer, a symbol or a placeholder, written `?` and its label, and every integer or symbol in a row is one its column allows. `rule <query> <Var> ... :- <item>, <item>, ...` adds a rule to a query. An item is an atom `<table>(<arg>, ...)` with one argument per column, each a variable, an integer, a symbol or `_`, or it is a condition `<Var> != <c>` where c is an integer or a symbol. Integers are decimal digits with no sign and no leading zero. Symbols and names are lowercase letters, digits and `_`, starting with a letter; a label is lowercase letters, digits and `_`; a variable is a capital letter followed by letters, digits and `_`. Every rule has at least one atom, atoms read tables and never queries, every variable in a rule's head or in one of its conditions also appears in one of its atoms, and all the rules of a query have the same number of head variables, which may be none.

A label is one value everywhere it appears. The values a placeholder may take are the values allowed by every column it sits in, and there is always at least one. A filling gives each placeholder one of the values it may take, and nothing else constrains it: two placeholders may take the same value, and a value need not appear anywhere else in the program. Under a filling every row holds only integers and symbols.

Under a filling, a rule derives its head, the values of its head variables in the order written, once for each choice of one row per atom that fits: a constant argument equals the row's value in that column, `_` fits anything, a variable takes one value everywhere it appears in the rule, and every condition of the rule holds. `X != c` holds when the value X takes is not c. An integer never equals a symbol. A query returns every row that any of its rules derives.

The report of a query holds, once each, the rows of integers and symbols that the query returns under every filling, and nothing else. A placeholder never appears in a report. The queries print in the order of their first rule, each as a line `ans <query> <n>`, where n is the number of rows, followed by one line per row: the query name and then its values, separated by single spaces. Rows are sorted on their first value, then their second, and so on. Integers come before symbols, integers compare as numbers, and symbols compare character by character in ASCII order, a prefix first. A query with no head variables reports at most one row, the empty one, printed as the query name alone.

The engine we have gets this wrong. Run `/app/run_ask.py` on `/app/progs/tiny.txt`. The first line comes out `ans pair 1`. That is wrong. It should be `ans pair 6`: the first two rows of `ev` hold the same `?w`, so they join each other and themselves whatever value it takes, and the row holding `?v` joins itself.

`/app/run_ask.py` reads a program with `/app/rs/load.py`, passes the store it builds to `report` in `/app/rs/keep.py`, and prints what that returns with `/app/rs/say.py`, which sorts the rows and drops repeats. `report` returns a mapping from each query name to the rows it reports, each row a tuple holding its integers as ints and its symbols as strs; a query it leaves out prints with no rows. The files you may change are `/app/rs/cmp.py`, `/app/rs/join.py` and `/app/rs/keep.py`. Nothing else is collected: we copy those three into a clean copy of the rest of `/app`, so a change to any other file, or a new file, is never seen.

Two of the big ones are in `/app/progs`. There `wide.txt` has nineteen thousand rows and eight thousand placeholders, and `flags.txt` has six thousand rows and 3600 placeholders. We grade thirty-three small programs of our own, three hundred small programs generated after you finish, and three programs built like each of the big two. Every line of every report has to be exactly right. The whole set runs one program after another in a single Python 3.12 process with only the standard library, on one CPU with 2048 MB of memory, and it has to finish inside 300 seconds.
