`/app` is the commit path of a keyed store, cut down to the part that decides whether a transaction is still entitled to go through. A program is a text file of ops and `/app/progs` holds four of them. `open t` starts transaction t, `seal t` ends it by committing and `drop t` ends it without. Between those, `get t k` reads one key and `span t lo hi n` reads at most n rows from lo to hi, while `put t k v` gives key k the value v and `del t k` takes k away; `mark t s` puts down a mark named s, and `back t s` rolls the transaction back to it. Outside all of that, `look lo hi` prints the committed rows of a range. Keys and values are non-negative whole numbers, n is at least 1, lo is at most hi, a transaction number is used once, every op names a transaction that is open, and every `back` names a mark its transaction still has. `/app/run_tx.py` takes a program and prints a line for each thing that happens.

The fourth line comes out `dead 2 1` and should read `dead 2 0`: transaction 2 opened before anything had been committed, so its scan was answered from no rows at all, and that was already an answer it could not have given again.

The files you may change are `/app/tx/rows.py`, `/app/tx/hold.py`, `/app/tx/view.py`, `/app/tx/cover.py`, `/app/tx/watch.py` and `/app/tx/path.py`. Nothing else. The rest of the tree is replaced by our own copy before a program is run, a new file put beside those six included.

A transaction is opened against the rows as they stand at that moment, and that is what its reads are answered from: those rows, under the transaction's own changes that were made before the read and have not been taken back. `get` prints the value, or `-` when the key is not there. `span` returns the first n rows from lo to hi in key order, and all of them when fewer than n are there. A key the transaction has made itself is one of its rows; a key it has taken away is not.

Every `get`, `span`, `put` and `del` a transaction makes is a claim. Claims are numbered from 0 in the order the ops appear, and an op a rollback later takes back keeps its number.

A read claim stands while answering it again the same way, against the rows committed now, would return exactly what it returned. What a read is drawn from is its key, for a `get`; for a `span` that came back with n rows it is the keys from lo up to the last row returned, and for one that came back with fewer it is the whole of lo to hi. A change claim stands while it has not been taken back and no transaction that committed after this one opened has written its key, whatever value that commit wrote. A change that has been taken back claims nothing.

Claims are judged three times over: when a claim is made, after every commit that goes through, and after every rollback. The moment a standing claim stops standing the transaction is dead, and `dead <t> <i>` is printed with the lowest index among the claims that stopped standing at that moment, once for that transaction and never again. A claim that has stopped standing does not start standing again when the rows move back. A dead transaction goes on taking ops and answering reads.

`back t s` takes back the changes the transaction made after the last mark named s that it still has. It takes them back by position, not by key, so a key written both before and after that mark keeps what it was given before it. The mark stays and can be rolled back to again; marks put down after it are gone. Reads are not taken back.

A transaction that is not dead commits when it seals: the last standing change of each key it holds is applied to the rows, `seal <t> ok` is printed, and then the other open transactions are judged, lowest transaction number first. A dead one applies nothing and prints `seal <t> no <i>` with the index it died at. `drop t` ends a transaction without applying anything.

The lines are `read <t> <k> <v>`, with `-` for a key that is not there; `span <t> <k>:<v> <k>:<v> ...`, with `-` when it returns no rows; `dead <t> <i>`; `seal <t> ok`; `seal <t> no <i>`; and `look <k>:<v> ...`, with `-` for a range holding none. A read prints its answer before anything else its op causes. A change, a mark, a rollback and a drop print nothing themselves. Nothing else is printed.
