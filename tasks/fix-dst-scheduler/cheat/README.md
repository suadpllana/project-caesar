# The adversarial suite

Thirty-nine attempts, every one of which must score 0. They are generated by
`authoring/fix-dst-scheduler/emit.py` from the wrong readings and the attack payloads, never
written by hand, so a reading that is repaired cannot leave a stale cheat behind testing the
version before the repair.

`cheat-rule-*` (24) is one complete planner per wrong reading of the contract. Sixteen read the
clock, the windows, the pools or the worker wrongly: the repeated local minute taken early, the
impossible one taken naively, a clock cadence advanced in elapsed time, a follow cadence advanced
from the nominal, a drop that does not anchor the chain, a capped run holding the slot shut, the
ledger keyed to the job's zone, the charge taken at the end, a deadline computed by arithmetic
that a shift invalidates, a worker never re-examined when a pool day rolls, both window
boundaries flipped, an inclusive deadline, a running occurrence that fails to suppress the next,
ends settled after arrivals, and an index that counts only the runs that happened. Eight read the
reservation wrongly: no reservation at all, which is the planner the shipped sweep suggests and
the one every agent in the first probe round handed in; a higher start exactly at the end of the
run treated as an obstacle; only the next due instants of the higher jobs consulted, without
their windows, pools or waiting occurrences; only the single highest job planned ahead; the
higher jobs planned ahead without the rule among themselves; only the higher occurrences already
waiting planned ahead; the pools judged after this start's charge instead of before it; and a
projection that stops at the horizon. Each is reachable - an agent could hand exactly this in -
and each is separated by the enumerated plan named for its rule.

`cheat-flat-*` (5) is the dumb end: an empty trace, every occurrence started on its nominal, every
occurrence dropped on its nominal, only the first job, and the printout from the brief replayed.
The last one matches nothing at all, because what the brief prints is the shipped planner's wrong
answer rather than a correct one.

`cheat-probe-*` (10) attacks the verifier rather than the problem, and each pairs its payload with
a planner that is wrong on its own, so a 1 could only come from the attack succeeding: a
double-forked process writing the reward after the tests return, a planted verdict in the worker's
report, a plant followed by an exit before the grader looks, values built to throw inside the
grader, a probe that writes to every root-owned verifier path, a planner with nothing of its own
that reads the frozen answers and the sealed model, the record type restored inside `run()` after
the verifier armed it, correct lines handed back from a record type the verifier never sees, a
planner leaning on a change to a file that is not collected, and `cheat-probe-answer-key.sh`,
which carries the whole of `tests/gt.json` verbatim, reproduces all 32 frozen answers, and is
caught only by the plans this run generated from its own nonce.

`authoring/fix-dst-scheduler/cheat_report.py` runs them all in the two containers and prints the
test that caught each one, because a cheat that scores 0 for its own reasons proves nothing.
