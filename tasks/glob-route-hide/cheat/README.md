# Cheat attempts

Each script writes all five resolution files into `/app/fe/`, which is the only place the verifier collects submitted code from, and each must score 0. They are generated by `authoring/glob-route-hide/emit.py` from the reference or the shipped resolver with one asserted change each, and this list is written by the same run.

## Wrong readings (30)

The reference with one rule read another way, each caught by what it prints: first by the hand case named beside it, and again by the generated programs. One, `memo-rec`, is also too slow for the large programs, so in the full verifier the clock stops it first.

- `cheat-pub-only.sh` - a line passes on only what is public; private lines never leave their module (caught by `vis-child-sees`)
- `cheat-string-prefix.sh` - a module counts as inside another when its path merely starts with the other's, dots or not (caught by `vis-sibling-prefix`)
- `cheat-no-narrow.sh` - an import passes a candidate on as widely as it came, whatever the line's own visibility (caught by `narrow-private-glob`)
- `cheat-glob-no-narrow.sh` - a private glob passes things on as widely as they came (caught by `narrow-private-glob`)
- `cheat-explicit-no-narrow.sh` - a private explicit import passes its candidates on as widely as they came (caught by `narrow-explicit`)
- `cheat-pub-widens.sh` - a public line makes whatever it passes on public (caught by `narrow-keeps-item`)
- `cheat-explicit-ignores-vis.sh` - an explicit import takes whatever the source holds, seen or not (caught by `explicit-denied`)
- `cheat-first-route.sh` - a candidate keeps the visibility of the first route that delivered it (caught by `widen-two-routes`)
- `cheat-seen-hides.sh` - an own binding hides the globs only from readers that can see it (caught by `hide-own-private`)
- `cheat-broken-falls.sh` - an own import that finds nothing does not hide the globs (caught by `hide-broken`)
- `cheat-gated-hides.sh` - an own line whose flag is off still hides the globs (caught by `hide-gated-off`)
- `cheat-glob-all-names.sh` - globs give every name, including the ones the module binds itself (caught by `glob-unbound-name`)
- `cheat-missing-unbound.sh` - an import from a module the program does not declare binds nothing (caught by `missing-module`)
- `cheat-rename-binds-both.sh` - an import with a rename binds the old name as well as the new (caught by `rename-hides-bound`)
- `cheat-rename-keeps-name.sh` - an import with a rename binds and gives under the old name (caught by `rename-chain`)
- `cheat-use-no-hide.sh` - only item lines hide the globs; an explicit import does not (caught by `hide-own-private`)
- `cheat-display-held-name.sh` - a renamed item is printed under the name it is held by (caught by `rename-chain`)
- `cheat-glob-ignores-flags.sh` - a glob exists whatever its flag says (caught by `widen-gated-arm`)
- `cheat-item-ignores-flags.sh` - an item line exists whatever its flag says (caught by `gate-negated`)
- `cheat-negation-ignored.sh` - `if !F` is read as `if F` (caught by `gate-negated`)
- `cheat-route-dupes.sh` - an item reached through two of the module's globs is two candidates (caught by `route-same-item`)
- `cheat-drop-ambiguous.sh` - a glob gives nothing for a name that is ambiguous where it comes from (caught by `amb-carried`)
- `cheat-explicit-amb-broken.sh` - an explicit import of an ambiguous name gives nothing (caught by `amb-explicit`)
- `cheat-found-order.sh` - candidates are listed in the order the module's lines reach them (caught by `amb-two-globs`)
- `cheat-alpha-order.sh` - candidates are listed alphabetically (caught by `amb-file-order`)
- `cheat-dup-items-merged.sh` - two item lines with one module and name count as one candidate (caught by `dup-item-lines`)
- `cheat-no-broken.sh` - a name the module binds itself but gets nothing for prints unresolved (caught by `hide-broken`)
- `cheat-inherit.sh` - a module that gets nothing for a name falls back to its parent's names (caught by `vis-no-inherit`)
- `cheat-scc-share.sh` - every member of a cycle of globs holds the same candidates (caught by `cycle-cut`)
- `cheat-memo-rec.sh` - memoized recursion over (module, name); a pair already in progress gives nothing (caught by `cycle-fed`)

## Shortcuts (4)

Strategies that skip the resolution: a constant, the first candidate by position, the worked example replayed.

- `cheat-const-unresolved.sh` - shortcut: every reference prints unresolved, the commonest outcome
- `cheat-pos-first.sh` - shortcut: an ambiguity is settled on its first candidate in file order
- `cheat-pos-first-glob.sh` - shortcut: a module reads only its first glob
- `cheat-replay-example.sh` - shortcut: the brief's quoted line printed for every reference

## Forgery (1)

Everything the agent could collect about the hand cases, printed back verbatim. The generated programs are drawn after the agent's container is gone, so it has nothing to print for them.

- `cheat-forge-hand.sh` - forgery: tests/seal/gt.json carried verbatim, every hand answer returned for its program, the shipped resolver for other small programs and unresolved for large ones

## Isolation probes (9)

Each goes after one piece of the isolation, and the six that can observe it write what they saw to `/work/probe.log`. The three that carry a correct resolver - the sealed model if the seal can be read, a resolver in a sixth file, one pasted into the driver - would score 1 if that piece were missing. The rest sit on the shipped resolver, which fails honestly, so a 1 could only come from the attack. The answer key and the malformed output both finish inside the clock, so that what they return reaches the grader. `probe-privilege` and `probe-late-reward` need a second uid and a real fork to mean anything; the host emulation has both, running test.sh as root so that it drops the worker to uid 1002 with setpriv, as it does in the container.

- `cheat-probe-late-reward.sh` - probe: a double-forked survivor keeps writing 1 into the reward long after the worker returns
- `cheat-probe-privilege.sh` - probe: runs as which uid, and can it write the reward, the seal or the exam
- `cheat-probe-answer-key.sh` - probe: reads the frozen answers and imports the sealed model, and prints the model's lines for every program if the import works
- `cheat-probe-rewrite-exam.sh` - probe: rewrites every exam program into one with no references
- `cheat-probe-plant-exit.sh` - probe: plants a record claiming the shipped output for every exam program, then ends the worker cleanly before it can overwrite the plant
- `cheat-probe-crash-worker.sh` - probe: plants a passing-looking record and kills the worker with a non-zero status
- `cheat-probe-malformed.sh` - probe: every reference returns a dict instead of a line
- `cheat-probe-uncollected-file.sh` - probe: the resolver lives in a sixth file beside the five, which the verifier never collects
- `cheat-probe-engine-in-driver.sh` - probe: a correct resolver pasted into the driver, which the verifier replaces with its own copy

## Exact and too slow (4)

Correct on every program, and stopped by the 60 second clock or the 2 GB limit on the large ones. These are the structures the task is about not using.

- `cheat-slow-pairs.sh` - exact: one fixed point over (module, name) pairs, values as item-to-region maps
- `cheat-slow-tables.sh` - exact: a full table per module, one dict per module holding every binding it has
- `cheat-slow-lifo.sh` - exact: sets over bindings, strongly connected components in order, but a last-in-first-out worklist inside each
- `cheat-slow-sweep.sh` - exact and light on memory: one sweep of the module graph for each referenced name
