`/app` is the name-resolution pass of the compiler for our module language: the part that decides what every name in a program refers to. `/app/run_res.py` takes a program file and prints one line for each `ref` line in it. Six sample programs sit in `/app/progs`.

A program opens with a line reading `flags` and then the names of the flags that are on. Any other flag is off. `mod P` starts module `P`, and every line up to the next `mod` belongs to it. A path is one or more names joined by dots, where a name is a lowercase letter followed by lowercase letters and digits. A module is inside every module whose path is its own cut off at a dot, so `a.b.c` is inside `a.b` and inside `a`, while `ab` is inside nothing. The lines a module holds are `item N`, `use P::N`, `use P::N as K` and `use P::*`, any of which may begin with `pub` and end with `if F` or `if !F`, and `ref N`, which takes neither. A line ending in `if F` is there only while flag `F` is on. One ending in `if !F` is there only while it is off. A line that is not there does nothing at all.

The resolver we have came from an older compiler. It handles everyday programs and gets the rest wrong. Run `/app/run_res.py` on `/app/progs/tiny.txt` and its fourth line comes out `app emit ambiguous net.emit log.emit`, where it should read `app emit ambiguous log.emit net.emit`.

A `pub` line can be seen from every module. Any other line can be seen from its own module and from every module inside it, and nowhere else. Enclosing modules lend nothing: a module gets names only through its own lines.

What a module has under a name is a set of candidates. Each candidate is an item, together with the modules it can be seen from, and every `item` line is a separate item. `item N` gives its module that item under `N`, seen from wherever the line can be seen. `use P::N as K` gives its module, under `K`, each candidate that `P` has under `N` and the importing module can see, and from then on that candidate is seen only from the modules that can see both it and the `use` line. `use P::N` is the same under `N`. `use P::*` does the same under every name its module does not bind itself.

A module binds a name itself when an `item`, `use P::N` or `use Q::M as N` line for that name is there. It then has under that name exactly what those lines give, even if that is nothing, and never anything from its `use P::*` lines. That holds for every module reading it, including one that cannot see the lines that bind.

A module has a candidate only when a chain of these lines leads from it to the candidate's `item` line. Lines that only lead round a circle give nothing. Neither does a module the program never declares. When several chains reach the same item it is still one candidate, and it is seen from every module that any one of those chains lets see it.

`ref N` asks what its own module has under `N`, all of which that module can see. One candidate prints `<module> N <m>.<n>`, with `m` the module holding the candidate's `item` line and `n` the name on that line. No candidate prints `<module> N broken` if the module binds `N` itself, and `<module> N unresolved` if it does not. More than one prints `<module> N ambiguous` and then every candidate as `<m>.<n>`, in the order their `item` lines appear in the file. Fields are separated by single spaces. Lines come in the order of the `ref` lines, and nothing else is printed.

You may change `/app/fe/vis.py`, `/app/fe/own.py`, `/app/fe/glob.py`, `/app/fe/fix.py` and `/app/fe/say.py`, and only those. Before a program runs, everything outside those five files is replaced by our own copy, so a file you add beside them is never picked up. `/app/run_res.py` calls `settle(prog)` in `fix.py` once per program. It then calls `line(prog, tab, i)` in `say.py` for the `ref` line with index `i`, counting from 0 in file order, passing whatever `settle` returned as `tab`. Keep both functions with those names and arguments.
