`/app` is the recalculation core of our reporting grid. Since we rewrote it the engine has been bringing the wrong cells up to date. `/app/sheet/store.py` holds the cells and what each one shows. `/app/sheet/expr.py` reads formulas and evaluates them through a lookup object, and `/app/sheet/core.py` applies one edit and prints the report. What gets recomputed is decided in `/app/sheet/dep.py`, `/app/sheet/lay.py`, `/app/sheet/upd.py` and `/app/sheet/flow.py`. Those four you may change. Anything else you touch we check against the copy we shipped, once your work has run. The frozen side builds `Dep` and `Lay` and calls `flow.edit`, so leave those names where they are, taking what they take.

Hand `/app/run_sheet.py` a script and it prints two lines for each graded edit, where `<name>` is the script's file name without its suffix and `<k>` counts the graded edits from one. `<name> rc <k> <cell> <cell> ...` names the cells the engine recomputed, each once, sorted by row and then column. `<name> dv <k> <cell>=<value> ...` names the cells whose displayed value changed, in that same order, and a value is an integer, `-` for a cell showing nothing, or `#BLK`. An empty list prints as `-`. A script opens with `size <rows>`, the number of rows the sheet has, and continues with `set <cell> <integer>`, `set <cell> = <formula>` and `clr <cell>`. Cells are written `r3c2`. Lines before the `go` line are loaded without a report. Every line after it is one graded edit.

Run `/app/run_sheet.py /app/cases/ledger.txt`. Its third edit writes a number a cell already held. The engine answers `ledger rc 3 r1c3 r2c3 r3c3 r5c5` over `ledger dv 3 -`, so four cells were recomputed when nothing in the sheet moved at all. `/app/cases/roster.txt` is worse. Its first edit drops a `9` into a cell that a block was occupying and the engine prints `roster rc 1 -`, so nothing noticed; its last edit shortens that block and prints `roster dv 3 r1c1=2`, leaving the cells the block gave up still showing the numbers it had put in them. `/app/cases/board.txt` is a third script. This is not one bad line in one file.

A formula is built from integers, cell references, `+`, `-`, `*` and parentheses, over `SUM(<span>)`, `CNT(<span>)` and `IFZ(<test>, <then>, <else>)`. A span is written `r1c1:r5c2`. It covers that rectangle, row by row, and every cell in it is read, the empty ones included. `SUM` adds the numbers in a span and `CNT` counts the cells in it that show one, both passing over cells that show nothing; a bare reference to such a cell reads as zero. `IFZ` evaluates its test and then exactly one of the other two arguments. The arm it skips is not read at all. Any formula that reads a cell showing `#BLK` shows `#BLK` itself.

Three functions return a block of values rather than one. `RUN(<a>, <b>)` gives the integers from `a` to `b`, and nothing when `a` is past `b`. `LIST(<span>)` gives the numbers in the span in order. `TOP(<span>, <n>)` gives the `n` largest of them, biggest first, and nothing when `n` is not positive. One of these is the whole formula or it is not written at all.

A block sits in the cell holding the formula and continues into the cells directly under it, one element to a cell. It does not fit if its last cell would be off the bottom of the sheet, if a cell it would occupy holds its own content, or if it would occupy a cell the formula itself read. A block that does not fit shows `#BLK` and occupies nothing. Whether it fits or not, the formula reads whether each cell it would have occupied holds its own content, for every one of those cells that is on the sheet. A block with no elements shows nothing. When a block stops occupying a cell that cell shows nothing again, unless it has since been given its own content, in which case it keeps it. A cell that stops carrying a formula gives up whatever block it had laid down.

Now the rule the rewrite lost. We recompute a cell when one of the values its last evaluation read is not what that cell shows once the sheet has settled, and at no other time. A read is either the value a cell displays or whether a cell holds its own content. Both count. Writing anything into a cell leaves it with nothing read on record, so a formula put into a cell is always recomputed, even when the new formula reads the same cells to the same numbers as the old one did. A value that moves and comes back has not moved. A cell whose reads end where they started is a cell we did not need to touch, and reporting it is as wrong as missing one that did. We grade which cells were recomputed. The order you visited them in is yours.

Four ordinary behaviours carry the same weight in the grading as everything above. Writing a number a cell already holds recomputes nothing. A cell that is recomputed and comes out with the value it already had leaves its own readers alone. Content put into a cell that no block would ever reach is nobody's business but that cell's. And clearing a cell that a block is occupying, which has no content of its own to clear, changes nothing anywhere.

No script asks for a cell outside its sheet, nests a block-valued call inside a larger formula, or arranges a sheet where some formula ends up needing its own value. Our sheets are larger than the three you have. They reach three hundred and sixty rows, and a few are built up one cell at a time by some eighteen thousand edits, finishing with about twelve thousand formulas on them. Six hundred seconds is what the whole graded set gets. Asking every formula in the sheet whether it is out of date is exactly right. It does not get there.

Both printed lines of every graded edit are compared character for character, and one wrong line loses the run.
