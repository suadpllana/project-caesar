`/app` holds the loader of our extension host. A pack says what it provides, what it requires and which other packs it needs. A script tells the host what to load, what to use and what to drop. `/app/cases` holds three. `/app/run_host.py` takes one and prints what the host did, a row to a line.

A script carries packs and events together. `pk` opens a pack. Under it come its declarations: `pv` a name it provides, `rq` a name it requires, `wk` a name it requires weakly, `nd` a pack it needs, `st` a name it uses as it loads. Events are `ld` with a pack and either `open` or `own`, `us` with a pack and one or more names, and `dp` with a pack. Every load makes a resident. Residents number from one in the order they are made, and no number comes twice. The standing resident of a pack is whichever its last `ld` made and no `dp` has ended.

Each event prints a row, then exactly one `rl` row. An `ld` row lists what it made. In creation order, or `-`. A `us` row names the asker, the name and the number it reached. Instead of a number it carries `none` when nothing in that view provides the name, `bad` when the asker declares the name neither `rq` nor `wk`, or `off` when the pack named has no standing resident. An `off` row carries the first name. A `us` event with several names puts each later name to whatever the one before it reached, a row apiece. Chains stop at the first row without a number, and after any row naming a resident already gone. A `dp` row names what it ended, or `bad`. An `rl` row lists what went. Newest first, or `-`.

Some ground rules, several of which are not what you would do elsewhere.

A name means nothing to the host alone. It means something to one resident at one moment, and what it means is that resident's view: the resident, then the residents its needs stood at when it was made, then the open list. Resolving walks that order and takes the first provider. Anything released is in nobody's view.

The needs half settles when the resident is made and never moves again, and it holds residents, not pack names, so a needed pack dropped and loaded again carries nothing built against the old one over to the new, while a needed resident dropped but still resident stays in the view of everything built against it. Walk that half breadth-first from the `nd` lines in written order, each pack's needs behind it, adding nothing twice. The open half never settles. It is whatever stands open at the instant of the lookup, ordered by when those residents opened, so a resident does see packs opened long after it was made.

A resident that used a name has used it. The answer is written under that resident and that name and never changes, whatever loads or drops between, however much nearer a later provider would be. Asking again prints what was written. That holds for an answer since gone. It holds when the answer is nothing, which prints `none` every time. Names listed with `st` are used as that resident is made, in the view existing then. An `ld` of a pack already standing makes nothing. Asked for `open`, that resident goes on the end of the open list if it is off it, and nothing already written moves. Otherwise needs come up first, in `nd` order, each need's own needs before it, and the pack itself last, so everything is made before whatever reached it. A pack already standing is never made again, however it was reached. Needs come up `own`, however they were reached.

A `dp` ends the standing resident and takes it off the open list at once. From then nothing reaches it that way. Resident or not. What keeps a resident is that something can still use it. Everything still standing is kept. Whatever is kept keeps, for each name its pack lists with `rq`, the resident written under that name, and for a name not yet used, whatever it resolves to in that same view as things stand before anything is released. Something dropped is an asker like any other while kept, so its unused `rq` names hold things up too. What is not kept goes at once. Newest first. `wk` holds nothing up, used or not.

We grade both halves: releasing what could still be used is wrong, and keeping what nothing can reach is wrong just as hard, so a host releasing nothing scores what one releasing everything scores.

Four things have to keep working. We grade them as hard as the rest. A pack needing nothing, loaded `own`, resolves against its own provides and the open list, nothing more. A pack asked twice with `own` is made once. Two residents of one pack, one dropped and still resident, one standing, both answer, to different askers, at the same moment. A `dp` naming a pack that does not stand prints `bad`. Nothing goes.

The scripts we grade drop packs before every name they provide has been used. They drop a needed pack and load it again while a resident built against the old one still stands. They run chains beginning at a pack that stands and ending at one that does not. They hold dropped residents whose only claim is on each other. Needs never run in a circle. Every event names a pack the script declares.
