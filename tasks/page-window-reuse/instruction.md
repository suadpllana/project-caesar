`/app` is the memory manager of a token-generation service, cut down to the part that decides what is resident. A pool holds pages numbered from 1, a page holds a fixed number of tokens of one request's cache, and a request arrives with a prompt and the tokens it will emit. A program is a text file of ops, and `/app/progs` holds four of them. `pool n w a s b` sets the pool to `n` pages of `w` tokens each, `a` sink tokens, `s` window tokens and a budget of `b` tokens per step. `ask r p o` brings in request `r` with prompt `p` and output `o`, each written as comma separated `count:token` runs, or `-` for none. `bulk x k p t o` is the import shorthand that brings in `k` requests named `x0` upward, the i-th carrying prompt `p` followed by `t` copies of `1000+i`, and emitting `o` copies of `2000+i`. `step` runs one scheduling step, `stop r` cancels `r`, and `at r i` asks which page holds token `i` of request `r`. `/app/run_kv.py` takes a program and prints a line for each thing that happens.

The last line comes out `at a 0 none`, and it should read `at a 0 1`, since the first tokens of a request stay resident however far the rest of it has moved on. The files you may change are `/app/kv/pool.py`, `/app/kv/keep.py`, `/app/kv/live.py`, `/app/kv/fill.py`, `/app/kv/turn.py` and `/app/kv/put.py`. Nothing else.

A step decodes before it fills. Each resident request emits one token, in the order the requests became resident, until the budget of `b` tokens for that step is spent, and a request the budget does not reach emits nothing that step. What is left of the budget goes to the waiting prompts in arrival order. A prompt is taken up the first time a step reaches it with budget left. The walk below hands it the pages it can reuse, which costs no budget. What is left of the prompt is written a chunk at a time, one token of budget each, and a chunk ends on a page boundary unless it finishes the prompt. A budget too small to reach the next boundary therefore takes nothing at all, and that ends the filling for that step. Nothing jumps the queue. A request becomes resident in the step that completes its prompt and emits its first token in the next one.

While a prompt is being written its request holds every page of it, reused or written alike. Once the prompt is complete the request keeps only the pages holding any of its first `a` tokens and the pages holding any of its last `s` tokens, and lets the rest go. That same rule is applied again each time it emits a token, so a page falls out as the last `s` tokens move past it. A request letting go of more than one page at once lets them go in the order of the tokens they hold.

A page is named by its tokens and the page before it. A prompt is taken up by walking from its start: while a page holding the next `w` tokens of the prompt sits below the page before it, the request takes that page and the walk goes on, whether or not somebody else is holding it. The walk stops at the first page that is gone, whatever still sits below that one, and the prompt is written from there. Only a complete page is ever reused.

When the last holder of a page lets go of it, the page stays in the pool as reusable if a walk can still reach it, and goes back to the free pool at once if it cannot. A page for a request to write is taken from the lowest numbered free page; when there is none, the pool takes back the page released longest ago and takes with it every page below that one, those nobody holds going back to the free pool with it and those somebody holds staying until their holder lets go, never to be reached again, complete at the time or not. When there is nothing to take back either, the step ends with a preemption: the request that became resident most recently, or the request that asked for the page when none is resident, lets go of everything it holds and starts again from nothing later, keeping its place in arrival order. A fill asks for one page at a time. When a page fills and the same tokens already sit below the same page, the request hands its own page back to the free pool and takes the one that is already there.
Every line is printed when it happens. A prompt taken up prints `fill <request> <reused> <written>`, both counted in tokens, and prints that line again in any later step in which it writes. A preemption prints `hold <request>`. A take-back prints `gone <page> <pages back in the pool>`. A request that has emitted its last token lets go of everything and prints `done <request>`. The question prints `at <request> <token> <page>`, with `none` in place of the page when that request is not holding a page for that token, including when it has not got that far. A cancelled request lets go of everything it holds. It prints nothing. Nothing else is printed.
