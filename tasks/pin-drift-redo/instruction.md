`/app` is the write path of the record store, cut down to the part that decides what a transaction holds while it runs and what its close writes back. A program is a text file of ops. `/app/plans` holds four of them, and `/app/run_led.py` takes one and prints what the store said.

`cfg K` opens the key space: the keys are 0 to K-1 and each one stands at 0. `tx T` opens transaction T. Then `rd T k` reads a key, `put T k n` writes the number n into it, `add T k n` adds n to it, `cpy T k j` writes into k what the transaction has at j, `raw T k j` writes into k the number the transaction took at j, and `bmp T lo hi n` adds n to every key from lo up to but not including hi. `chk T k n` and `lim T k n` record a condition. `mk T` marks the work and `un T` throws work away. `fin T` closes the transaction; `drp T` abandons it. Programs are well formed. `cfg` comes first, and every key named is inside the key space. `bmp` has lo below hi. A transaction is used only between the `tx` that opens it and the `fin` or `drp` that ends it.

The files you may change are `/app/led/ver.py`, `/app/led/take.py`, `/app/led/hold.py`, `/app/led/work.py`, `/app/led/step.py` and `/app/led/close.py`. Nothing else. The rest of the tree is replaced by our own copy before a program is run, a new file put beside those six included. So `/app/run_led.py` is always ours. It makes one `ver.Store()` and then hands it every op as `step.one(store, box, op, out)`, where `box` is a dictionary it keeps for you and `out` is the list of lines it prints when the program ends. Both have to stay.

A transaction takes the number standing at a key the first time one of its ops names that key. `rd`, `put`, `add`, `chk` and `lim` name the key they are given. `cpy` and `raw` name both of theirs, and `bmp` names every key of its range. Before an op runs, every key it names whose taken number is no longer the number standing is taken again. The number a transaction has at a key is what its work makes of the numbers it has taken. The last entry in its work that sets that key decides it: `put` gives the number it names, `add` gives the number the transaction has at that key just before it plus n, `cpy` gives the number it has at j just before it, and `raw` gives the number it took at j. Where no entry of the work sets the key, the number the transaction has there is the number it took. Taking a number again therefore moves every number the transaction derived from that key, wherever in its work those sit.

`rd T k` prints `rd T k v` with the number the transaction has at k, and fixes it: the work gets an entry setting that key to the number printed. That entry is not a write. `mk T` marks the work. `un T` throws away the work from the last mark still standing through the end and that mark with it, or the whole work when no mark stands.

A condition is recorded where it is written. Nothing is tested while the transaction runs. `fin T` closes. Every key the transaction has taken whose number has moved is taken again, and the conditions are then tested in work order, each against the number the transaction has at its key at that condition's own position in the work. `chk T k n` holds when that number is n. `lim T k n` holds when it is n or more. A condition that does not hold throws away the work from the last mark still standing through that condition, the mark and the condition with it, and the testing carries on from the work after it with the numbers that mark opened on. A condition that does not hold with no mark standing before it ends the transaction with nothing written.

A close that ends that way prints `fin T no`. Any other close writes into every key that an entry of the surviving work sets, at the number the transaction has there once that work has run, and prints `fin T ok` followed by `k=v` for each of those keys in ascending key order, one space between. A close that writes into nothing prints `fin T ok` on its own. `drp T` ends a transaction with nothing written. It prints nothing. Neither does anything else: the only lines a program produces are one per read and one per close. Each transaction begins with nothing taken, no work and no marks.
