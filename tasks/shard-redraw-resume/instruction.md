`/app` is the run driver of our training stack, cut down to the part that decides which samples each rank takes and when run state moves. A program is a text file of ops. `/app/progs` holds four. `rows` says how many samples the set has, numbered from zero, `seed` seeds the shuffle, `rank` is the number of ranks the run opens on, `micro` is what one rank takes in one micro-batch, `accum` is how many micro-batches make an optimizer step, `ckpt` is the applied steps between checkpoints, `grow` is the applied steps in a row that lift the loss scale, `scale` is the exponent it opens at, and `epochs` is how many epochs the run is for. An `nf` names a sample that comes back non-finite. Then come the legs. `run n` attempts up to n steps, `kill` is a preemption, `back r` brings the run back on r ranks. `/app/run_train.py` takes a program and prints a line for each thing that happens.

The files you may change are `/app/rig/draw.py`, `/app/rig/cut.py`, `/app/rig/scal.py`, `/app/rig/turn.py`, `/app/rig/keep.py` and `/app/rig/lead.py`. Nothing else.

Each epoch is taken in an order drawn from the seed, the number of that epoch and the number of ranks the run is on, and `/app/rig/shuf.py` turns a position in that order into the sample standing at it. No epoch hands the same sample out twice. A step takes the next `rank * micro * accum` samples of the current order that the epoch has not handed out yet, and deals that window out in chunks of `micro`. Chunk `j * rank + r` is what rank `r` feeds on micro-batch `j`. Both are counted from zero. An epoch whose remaining samples will not fill another whole window is over, and what is left of it goes unhanded. That is settled before a step is attempted and not after one is taken, and leaving an epoch spends nothing out of the budget a `run` names. The run is finished once it has been through `epochs` of them, however much budget is left over.

A step is skipped when any sample in its window was named by `nf`. Skipped or not, that window has been read and the epoch stands that much further on. What a skipped step does not do is count toward the applied total. It halves the loss scale and ends the run of successes. The scale stops at an exponent of zero. Going `grow` applied steps with nothing skipped between them doubles it instead, and starts a fresh run of successes.

A checkpoint is written after every `ckpt` applied steps, holding the run as that step left it. A `kill` puts the run back at the last checkpoint. With none written yet it goes back to where the run began. A `back` changes the number of ranks from that moment on.

Every line is printed when it happens. The window a step read prints one `feed <rank> <sample ids>` line per rank, in rank order, with each rank's ids in the order it read them. Then the step prints `step <applied so far> <scale exponent>`, or `skip <scale exponent>` when it was skipped. A checkpoint prints `save <applied so far> <epoch> <samples the epoch has handed out>`. A preemption prints `kill <epoch> <samples handed out>`, a return prints `back <ranks>`, and leaving an epoch prints `roll <the epoch now open>`. The last line of every program is `halt <applied so far>`. Nothing else is printed.

`/app/progs/wide.txt` is sixty million samples. `/app/progs/deep.txt` is four hundred preemptions and returns across one run.
