`/app` is the part of a training run that decides what a step actually changes. A program is a text file of ops and `/app/progs` holds a few. `par` declares a parameter and how many slots it has, `grd` adds to what is pending on each of its slots, `frz` and `thw` take a parameter out of the run and put it back, `ws` sets the world size, `bud` sets what one rank may spend in one step, `step` runs a step, `save` and `load` write and restore a checkpoint, and of the three questions `own` asks what a rank holds while `val` asks for the values of a parameter and `mom` for its moments. `/app/run_fit.py` takes a program and prints a line for each question it meets.

The live parameters lie end to end in a map. That map is laid again at a step, and only at a step, and only when a parameter has been declared, frozen or thawed or the world size has been set since it was last laid. A parameter already there stays put. One that is no longer live comes out, losing its moments and keeping its values and whatever is pending on it, while a newly live one goes on the end, behind everything already there; several joining at the same step go in the order they became live. Number the map slots from zero, end to end. With `t` of them and a world size of `w`, each rank in turn holds the next `ceil(t/w)`. The last rank to hold anything is short. A rank past the end of the map, or past the world size, holds none, and a boundary falls wherever that arithmetic puts it, not at the edge of a parameter.

At a step every rank walks the slots it holds, in order, from the first of them. The running total starts at nothing. A slot with nothing pending costs nothing and is passed over as it stands. Any other slot costs the size of what is pending on it. The rank applies it while that total stays within the budget. The first slot it cannot afford stops the rank there, and that slot and everything behind it in the same shard keep what is pending for a later step. Applying a slot adds what was pending to its moment, takes the moment off its value, and leaves nothing pending. A gradient reaches every slot of the parameter it names whether or not that parameter is in the map.

A checkpoint is the value and the moment of every slot of the map, in flat order. Nothing else goes into it. Restoring one puts each pair back into the slot that position held when the checkpoint was written, and leaves what is pending, which parameters are live, the world size and the budget as they stand.

Asking what a rank holds prints `own <rank> <parameter> <offset>`, naming the slot that rank holds first and how far into its parameter that slot is, or `own <rank> none` where it holds nothing. Asking for values prints `val <name>` and then the value of each slot of that parameter, in order, as `<count>x<value>` groups, one group to each run of equal values. `mom <name>` prints the moments the same way. Nothing else prints.
