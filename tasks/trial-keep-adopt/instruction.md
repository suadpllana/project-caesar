`/app` is the evaluation path of a derived-field service, cut down to the part that decides what a question costs. A field is either a source, which carries whatever was last published to it and 0 until something is, or a derived field, defined once by one form over fields defined before it. A program is a text file of ops and `/app/progs` holds four of them. `def n raw` declares a source. The four derived forms are `def n sum a b`, taking two or more fields and worth their total, `def n cap a k`, taking a field and a number and worth the smaller of the two, `def n pick g a b`, worth `a` when `g` is not zero and `b` when it is, and `def n gate g a`, worth `a` when `g` is not zero and 0 when it is. Then `set n v` publishes `v` to a source, `ask n` asks for a field's value, `pin n` freezes a derived field and `free n` releases it, `try n v` opens a preview block that `end` closes, and `bulk t c s` is the import shorthand that declares, for every `i` below `c`, the source `tai`, `tbi` as a cap of it at 500 and `tci` as the sum of `tbi` with itself, publishing `i % s + 1` to each source as it goes. `/app/run_fld.py` takes a program and prints a line for each thing the service does.

The first two lines come out `run z` then `run y`, and they should read `run y` then `run z`, because a line is written when a field's evaluation finishes and the fields it read therefore stand above it. The files you may change are `/app/fld/keep.py`, `/app/fld/look.py`, `/app/fld/make.py`, `/app/fld/need.py`, `/app/fld/feed.py` and `/app/fld/hold.py`. Nothing else: the rest of the tree, the driver and the line writer among it, is used exactly as shipped.

A question evaluates a derived field only when the service cannot show that the value it already has still stands, and nothing but a question ever makes a field evaluate. One that has never been evaluated is evaluated. One that has is checked: the fields its last evaluation read are asked for again, in the order it read them, and each is compared with the value it returned then. That check stops at the first read that comes back different, the reads recorded after it are not asked for at all, and the field is evaluated. A check whose reads all come back with the values they had keeps the value and writes nothing. A source is never evaluated.

An evaluation takes its reads where its form takes them. A sum reads its fields left to right, a cap reads its field, a pick reads its guard and then one arm, and a gate reads its guard and then its field only when that guard is not zero. What it read, in that order and with a field it read twice appearing twice, is the record the next check walks, and it replaces whatever the field recorded before.

Publishing to a source the value it already carries does nothing whatever.

A preview block asks what publishing a value would produce without publishing it, and holds nothing but questions. Inside one the named source reads as the named value. A field whose check passes under that value keeps what it had and is not evaluated; a field that is evaluated inside the block leaves the results held outside it exactly as they were, and what it produced belongs to the block. Those results outlive the block. Publishing that same value to that same source makes them the service's own, publishing a different value to that source throws them away, opening another block throws them away, and publishing to any other source leaves them standing. A result taken over that way is checked like any other, so a field whose reads moved while it stood is evaluated again.

A pinned field stands at the value it was pinned at. It is never evaluated and the fields it reads are never asked for on its account, until it is freed, after which it is checked against the reads of its last evaluation however long ago that was. Pinning asks for the field first, so a field with nothing to stand on is evaluated by the pin, and the value the pin fixes is the one that question produced.

A field's evaluation writes `run <name>` and a question writes `val <name> <value>`, each as it happens. Nothing else is written.

`/app/progs/wide.txt` imports twenty thousand chains of three fields, asks for the end of every one of them, and then opens twenty thousand preview blocks, each over one chain's source. `/app/progs/deep.txt` builds a ladder of thirty diamonds, every rung read twice by the rung above it, and asks for the top of the ladder twice after each of two thousand publications to the source beneath it.
